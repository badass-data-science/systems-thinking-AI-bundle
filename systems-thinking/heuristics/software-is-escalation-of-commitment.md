title: Moving to software is an escalation of commitment
summary: Graduating a model to simulation software or code buys precision and shareability but costs a learning curve, a model fewer people can read or argue with, and a new way to be wrong (mistaking "it runs" for "it's correct").
chapters: [17]
when: Deciding whether a model should leave the spreadsheet or whiteboard.
then: Write the specific need that justifies each option (spreadsheet, dedicated software, PySD) and move only when the question requires it, such as many stocks, several analysts, or thousands of parameter combinations.
links:
  related: [choose-simulation-tooling, structural-and-behavioral-validity]
---

"The software would be nicer" is not a trigger. "We need to test a thousand parameter combinations" is.
